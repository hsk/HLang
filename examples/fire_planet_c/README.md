# FIRE PLANET（V9968 + geo3d、hlcc）

溶岩の海の上を、炎のアーチをくぐりながら飛ぶデモです。MSX（V9968 と geo3d）で動きます。溶岩の床（奥行きの輪切りの板）、プロミネンスのアーチ（粒ごとの板）、空の帯（色の面 6 枚）を、すべて geo3d の板で描きます。C で書いて hlcc で ROM（16KB）にします。

```sh
make R800=1        # fire.rom
make R800=1 run    # openMSX で動かす（OPENMSX=... で場所を指す）
```

要るものは、V9968 と geo3d のある openMSX（マシン `C-BIOS_V9968_JP`）です。`R800=1` は R800 のマシンで動かし、掛け算に R800 の命令を使います（その ROM は Z80 では動きません）。`R800=1` なしなら Z80 で動きます。

録画: `make R800=1 recrun` で、openMSX で遊んだ画面を録画します。ウィンドウを閉じると `fire.mp4`（H.264、768x636、30fps、音なし）ができて、そのまま Twitter に上げられます（140 秒まで。要 ffmpeg）。

操作: 自動で、手前のアーチの門をくぐります。カーソルキーで自分で飛び、A でオートパイロットに戻ります。

## 作り

- 板は 38 枚です（溶岩の床 16、アーチ 2 つ × 粒 8、空の帯 6）。絵は 32x32 の火の玉 1 種と、64x32 の溶岩 1 種（縦横につながる絵）とそのミップ 4 段です。
- 16 色のパレットで、0 番は透明（LOP = TIMP）です。
- 世界は y が上向きで、溶岩の面が 0 です。カメラは平行移動と、ロールの行列だけです。板も空の帯も一緒に傾きます。
- 板はカメラの方を向く四角です。四隅は、中心から大きさの半分だけずらした点で、毎フレーム Z80 が計算して geo3d に送ります。奥から順に並べるのも、画面の外を切るのも geo3d です。遠すぎる、近すぎる板は、カメラの後ろに置いて描かせません。
- 頂点は 38 × 4 = 152 個で、geo3d の拡張モード（10 ビットの番号）にして、4 つに分けて変換します。
- MSX の RAM は 0xE000 から 0xF380 までしか使えないので、頂点を RAM に溜めず、作りながら送ります。

### 空

上の 6 本の色の帯を、奥行き 3375 に置いた色だけの大きな四角 6 枚にします。地平線（カメラの高さで上下する）の少し上までで、下は溶岩の床が覆うので描きません。傾けても縁がきれいな直線になります。

### アーチ

- 節は、半円に、うねりと傾きを足した式で作り、アーチが手前を過ぎたときに作り直します。向きは固定です。
- 粒は輪（`RS` = 24 マス）の上を回ります。輪のうち `ARC` = 16 マスがアーチ（地面の上）で、残りの 8 マスは地面の下（描かない）です。8 個の連なり（`NP`）が、足の 1 か所（噴火口）から吹き出し、アーチを越えて、もう一方の足で地面に消えます。連なりが地面の下にいる間は、アーチは完全に空です。足では粒が点になるので、出入りは見えません。
- `RS` を 32、`NC` を 2 にすると、8 個の連なりが 2 つで、空白も 2 つです（板は 16 枚増えて、遅くなります）。
- 粒の位置、高さ、奥行き、大きさは、節と節の間で直線に混ぜます。流れる速さは 1 フレームに 0.4〜0.6 マスです。

### 溶岩の床

`y = 0` の水平な板を、奥行きの輪切り（`NR` = 16 枚、1 枚の奥行き `DZ` = 200）にしたものです。輪切りは手前へ来て（`LFWD`、アーチの 2 倍の速さ）、手前を過ぎたら一番奥へ回ります。横は 1 枚で、カメラの x に付いてきます。

- 絵は、64x32 を横に 4 回並べた 256x32 です。縦にも横にもつながるので、継ぎ目も穴もありません。
- 奥では板が画面の横を覆えなくなるので、ミップ（4 段）を使います。段 k の板は、半分の幅を 600 × 2^k にして、絵は模様 1 個の幅を 1/2^k にします。奥の辺が 460、920、1850 より遠いと、段 1、2、3 を使います。段の絵は、起動時に Z80 が基の絵から作ります。
- 今の制限: 絵は板に付いていて、カメラが左右に動くと、床の模様が世界に対して動きません。geo3d の uv が 8 ビットなので、模様をずらして貼れません。

## 速さ

openMSX で、フレームの数を 10 秒間数えました（板 43 枚のとき R800 で 27.5fps。空を 11 枚から 6 枚に減らした今は測り直していません）。

重いのは、板の数に比例する部分（頂点を送る、geo3d の変換、描く）で、板 1 枚で 0.5ms ほどかかります。頂点は 1 フレームに約 1KB 送ります。板が毎フレーム動くので、頂点を起動時に一度だけ送る手は使えません。

板を減らすなら、`main.c` の `NR`、`NA`、`NC`、`NP` を変えます（面と頂点の数は自動で変わります）。

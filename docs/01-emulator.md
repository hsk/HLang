# 1. エミュレータ

コンパイラを作る前に、出した機械語を走らせる場所を用意します。[emu/z80.ml](../emu/z80.ml) の 1 ファイルです。小ささと見やすさを優先しました。

## 命令コードを 8 進で読む

Z80 の命令コードは、2bit・3bit・3bit に区切ると規則が見えます。

```text
  7 6   5 4 3   2 1 0
 ┌───┬───────┬───────┐
 │ x │   y   │   z   │      p = y の上位 2bit、q = y の最下位 bit
 └───┴───────┴───────┘
```

- `x = 1` は `LD r,r'`。`y` が書き込み先、`z` が読み出し元のレジスタ番号です。
- `x = 2` は A との演算。`y` が演算の種類（ADD ADC SUB SBC AND XOR OR CP）、`z` が相手です。
- レジスタ番号は `B C D E H L (HL) A` の順で 0〜7 です。

だから、レジスタは配列 `r` に番号順で置きます。`LD r,r'` は `r.(y) <- r.(z)` の 1 行になります。命令ごとの表を書かなくても、番号がそのまま添字になるので、表を引くのと同じ小ささになります。

6 番は「(HL) の指すメモリ」なので、配列の 6 番は空いています。そこにフラグ F を置きました。

## IX/IY は HL の読み替え

`DD` や `FD` が前に付くと、HL の代わりに IX や IY を使います。エミュレータでは「いま HL 役をする組の位置」を `hl` という変数 1 つで持ちます。

```ocaml
mutable hl : int;              (* いま HL 役をする組の位置: 4=HL 8=IX 10=IY *)
```

配列 `r` の 8〜11 番に IX と IY を置き、前置バイトを読んだら `hl` を 8 か 10 にして、同じ命令の処理をもう一度呼ぶだけです。`(HL)` の番地を求める `ea` が、`hl` を見て `(IX+d)` に読み替えます。

## 時間はバスの動きに課金する

Z80 の時間は T ステートで数えます。命令ごとの時間の表は持たず、ハードウェアの動きどおりに足します。

| 動き | T ステート |
| --- | --- |
| 命令フェッチ | 4 |
| メモリの読み書き | 3 |
| I/O | 4 |
| 内部動作 | `tick` で明示 |

たとえば `LD A,(HL)` はフェッチ 4 + 読み 3 で 7、`LD A,(IX+d)` はフェッチ 4 + フェッチ 4 + d の読み 3 + 番地計算 5 + 読み 3 で 19 です。IX が遅い理由が、コードにそのまま書いてあります。

## 正しさの確かめ方

エミュレータが間違っていると、その上の検証が全部無意味になります。独立した 3 つの資料と突き合わせました。

- **zexdoc / zexall**：実機の結果から作られた命令網羅テストです。zexall は非公式のフラグ（bit3、bit5）まで照合します。どちらも全 67 項目が通ります。
- **z80emu（Lin Ke-Fong 作）**：zexdoc 全体の合計 T ステートが 46,734,978,649 で、1 の位まで一致します。
- **cz80d の表**：公式の全 697 命令について、命令ごとの T ステートを比べました。違ったのは 11 命令で、どれも表の側の書き間違い（19 が 9 になっている）でした。

```sh
dune exec test/zex.exe -- path/to/zexall.com
```

実装していないのは、EI 直後の 1 命令は割り込まないという遅延と、NMI です。

# 11. C フロントエンド（hlcc）

`hlcc` は、SDCC の書き方の C（サブセット）を、hlang と同じバックエンドでコンパイルするコマンドです。C を hlang の構文木（3 章の `Ast`）に直して、型検査から先は `hlc` と同じ道を通します。置き場所の探索、呼び出し規約の決め方、ループの最適化は、すべてそのまま効きます。

```sh
dune exec bin/hlcc.exe -- examples/hello.c --run      # エミュレータで走らせる
dune exec bin/hlcc.exe -- main.c App.c Game.c         # main.rom（ファイルはまとめて 1 つのプログラム）
dune exec bin/hlcc.exe -- main.c --asm                # アセンブリを見る
```

受ける C の範囲は、10 章の調査（damaxian の C 版を数えたもの）で決めました。

## 全体の流れ

```text
.c ──Cpp──▶ 字句（マクロ展開済み）──Cparse──▶ C の構文木 ──Clower──▶ hlang の構文木 ──▶（hlc と同じ）
                                                       ▲
                                    #include "x.hl" の関数の型（Parse で読む）
```

| ファイル | すること |
| --- | --- |
| [src/cpp.ml](../src/cpp.ml) | 字句解析とプリプロセッサ。`#define`（関数形式、`#`、`##`、`__VA_ARGS__`）、`#include`、`#if` `#ifdef` `#elif` `#else` |
| [src/cparse.ml](../src/cparse.ml) | 構文解析。型の名前（typedef）を覚えながら読む。構造体と共用体（無名のメンバー）、列挙、宣言子 |
| [src/clower.ml](../src/clower.ml) | 型を付けて、hlang の構文木に直す。この章の中心 |
| [src/casm.ml](../src/casm.ml) | インラインアセンブラ（SDCC の書き方）を、組み立ての行にする |
| [bin/hlcc.ml](../bin/hlcc.ml) | コマンド |

構文解析は手書きです（hlang の他の解析と同じ。ライブラリに頼らない）。C は型の名前かどうかで読み方が変わる（`(T)*x` はキャストか掛け算か）ので、menhir を使っても字句解析に型名の表を持たせる工夫が要り、あまり小さくなりません。

## C の意味を守る

10 章の調査のとおり、C のコードは整数の格上げに意味を頼っています。`u8` どうしの `a + b` は、C では int（SDCC では 16 ビット）で計算されます。

```c
u8 a = 200, b = 100;
if (a + b > 255) ...     /* 成り立つ（300 > 255） */
u8 c = a + b;            /* 44（代入で 8 ビットに丸める） */
```

hlang の `+` は、型の幅のまま計算します（u8 なら 256 で割った余り）。そこで Clower は、C の型を自分で付けて、格上げを明示的なキャストとして書き出します。`a + b > 255` は `(a as i16) + (b as i16) > 255` になります。

ただし、全部を 16 ビットで計算すると遅くなります。結果の下位 8 ビットしか使わない所では、初めから 8 ビットで計算する式を出します（`rv8`）。

- `u8` への代入、`(u8)` のキャスト、`u8` の引数。`+ - * & | ^ ~ <<` の結果の下位 8 ビットは、引数の下位 8 ビットだけで決まるので、中も 8 ビットのまま計算できる。
- 比べる値の両方が 0〜255 に入ると分かれば（`fits8`。u8 の変数、0〜255 の定数、u8 との `&`、比較の結果など）、8 ビットで比べる。両方が -128〜127 に入るなら、符号付きの 8 ビットで比べる。
- `if (x & 0x80)` のように 0 と比べるだけの所も、値が 0〜255 に入るなら 8 ビットで比べる。

8 ビットで済まない所は 16 ビットのまま出します。hlang の最適化（Narrow、5 章）が、さらに狭められる所を狭めます。

SDCC と同じにしてあること:

- `char` は符号なし。`int` と `short` は 16 ビット。`long` と浮動小数点は受けない（エラーにする）。
- 構造体に詰め物を入れない（`sizeof` は中身のバイト数の合計）。
- 数の前の `#`（`#0x10`）、二進の `0b0101`、名前の `$`。
- 構造体そのものをポインタにキャストすると、その番地になる（`(u8*)videoTransfer`）。

## 置き場所

| C | hlang |
| --- | --- |
| 局所変数、引数（スカラー） | 変数（`let`）。置き場所は探索が決める |
| 大域のスカラー | 大域変数（`var`） |
| 配列、構造体、番地を取られる変数（`&x`） | `[u8; バイト数]` の配列。読み書きは `mem[番地 + 位置]` |
| `const` の配列・構造体（中身が定数） | ROM の表（`data`） |
| `const` のスカラー（定数で初期化） | 定数（使う所に値が入る） |
| 局所の配列・構造体、`static` の局所変数 | 関数ごとの固定の配列（hlang には再帰がないので、それで正しい） |
| 文字列 | ROM の表（`cstr.N`）。同じ文字列は 1 つにまとめる |

構造体と配列のバイトの位置は、Clower が計算します。`p->x` は `mem16[p + x の位置]`、`a[i]` は `mem[a + i × 要素の大きさ]` です。256 バイト以下の配列を 8 ビットの添字で引くときは、添字を 8 ビットで計算します（hlang の表と同じ形なので、添字をポインタに直す最適化（6 章）も効きます）。

無名の構造体・共用体のメンバーは、外の名前として見えます。damaxian の固定小数点は、こう書いてあります。

```c
typedef struct {
    union {
        struct { u8 xd; u8 xi; };   /* 下位・上位のバイト */
        i16 x;                      /* 16 ビットの固定小数点 */
    };
} ENEMY;
```

`e->x` も `e->xi` も、同じ番地からの位置を計算するだけです（`xi` は `x` の 1 バイト上）。

中身に番地を含む `const` の表（`const u8* const t[] = { a, b }`）は、hlang の表に整数しか書けないので、RAM に置き、起動時に番地を書き込みます。初期値のある RAM の配列も、起動時に ROM の表から `copy` します。起動時の処理は、`main` の先頭に入ります。

## 式に副作用があるとき

hlang の式には副作用がありません。C の `x = y++`、`f(a = 1)`、`c ? a : b` は、文を前に出して書きます（`env.pre`）。

```c
s += *p++;     /* t = mem[p]; p = p + 1; s = s + t */
```

前に出した文の後で値を読むので、順番が変わらないよう、関数の戻り値も一時変数へ受けます。`*p++` を読むときと書くときは、hlang の `next(p)` と同じ形（読む、進める）にします。HL や IX で歩くコードになります。

前に出す文があると困る所は、形を変えます。

- `while` の条件: 毎回調べ直すので、`loop { 前の文; if !条件 { break }; 本体 }` にする。
- `&&` と `||` の右側: 左側しだいで実行されないので、`if` で書く。

## u8 を int に広げない所

C では、u8 の値は計算の前に int（符号付き 16 ビット）に広げます。けれども、結果が同じなら 8 ビットで計算してかまいません（C の as-if 規則。SDCC もそうしています）。hlcc は、値が必ず 0〜255 に入る式（`fits8`）を見て、次の所を 8 ビットで計算します。

| 式 | 8 ビットにする条件 | 例 |
| --- | --- | --- |
| 比較 | 両辺が 0〜255 | `a >= BULLET_SIZE * 4` は `cp 0x48` 1 つ |
| `>>`（量が定数） | 左が 0〜255 | `(x & 0xc0) >> 3` は `srl a` 3 回 |
| `&` | どちらかが 0〜255 | `m & 0xf0`（m が負の i16 でも下位 8 ビットで決まる） |
| `\|` `^` | 両方が 0〜255 | |

定数の式（`3 * 24`）も、値を見て 0〜255 か調べます。`+`、`-`、`<<` を通った式は、繰り上がりや借りが比較に効くので広げたままにします（`w + 0x20 > 0xff`）。結果を u8 に戻す計算は、もともと 8 ビットです（`rv8`）。

damaxian の C 版では、16 ビットの符号付き比較が 21 か所から 12 か所に減りました（残りは C のソースが i16 で計算している当たり判定）。割り込み処理 1 回の平均は 47,120T → 44,777T です。

C のソースが本当に i16 で計算している所（damaxian の当たり判定の `i16 a = (i8)ix->xi - (i8)ship.x; if (a < 0) a = -a;`）のために、バックエンドも 3 つ直しました。hlang のプログラムにも効きます。

- **i8 から i16 への符号拡張**を IR の `Sext` にして、`ld l,a / add a,a / sbc a,a / ld h,a` で出す。前は「符号ビットを反転して広げ、0x80 を引く」16 ビットの計算だった。
- **符号付き 16 ビットの値と、下位バイトが 0 の定数（0、0x100、-256 など）の大小**は、上位バイトだけで比べる（cps.ml の `compare_s`）。`a < 0` は `ld a,h / cp 0x80` になる。
- **16 ビットの `^` `|` `&` で、定数のバイトが何も変えないとき**（`^ 0`、`| 0`、`& 0xff`）は、そのバイトの命令を出さない。符号付きの比較で両辺に掛ける `^ 0x8000` は、上位バイトだけになる。

damaxian の C 版は 44,777T → 43,617T、hlang の 02-tuned 版は 43,251T → 42,871T です。

## 文

| C | hlang |
| --- | --- |
| `for (u8 i = a; i < N; i++)`（N は定数、本体で i を変えない） | `for i in a..N`（hlang のループの形がそのまま使える） |
| その他の `for` | `while`。`continue` の前に step を置く |
| `do { } while (c)` | `loop { 本体; if !c { break } }`。`continue` の前に条件を調べる |
| `switch`（値が 0〜255、枝が break で終わる） | `match`（出し方は測って選ばれる、6 章） |
| `switch`（16 ビットの値） | `if` の連なり |
| 量が変数のシフト | 1 ビットずつずらすループ（hlang は定数の量しか書けない） |

## hlang のライブラリを使う

`#include "msx.hl"` のように `.hl` を取り込むと、hlang のライブラリとして読み込みます（`hlc` の `import` と同じ）。その中の関数（`extern fn` も）の型を読んで、C から呼べるようにします。hlang の組み込み（`di()` `ei()` `halt()` `copy(dst, src, n)` など）も呼べます。

## インラインアセンブラ

SDCC の書き方（sdasz80）の `__asm` … `__endasm` を受けます（[src/casm.ml](../src/casm.ml)）。

- **中のマクロも展開する。** SDCC のプリプロセッサはアセンブラの中も展開するので、`IFNZERO(0$)` のようなマクロが使われています。そこで、`__asm` の中もほかと同じく字句に分け、改行の位置（`Nl`）を残します。`;` から行末は注釈として捨てます。マクロは `\` で行をつなぐので、1 行に命令がいくつも並ぶことがあります（`ld a, x ld y, a`）。命令の名前で区切ります。
- **書き方を直して組み立てる。** 1 文ずつ ZMA の書き方のテキストにして、`Zma.parse_line`（9 章）で読みます。

| sdasz80 | 直した形 |
| --- | --- |
| `#0x10`、`#'A`、`#('9+1)` | `16`、`65`、`0+('9'+1)`（即値の `#` を取る。数は値にする。sdasz80 の `010` は 10 進、ZMA は 8 進なので） |
| `_name` | C の名前 `name` の hlang のラベル（関数か、メモリに置いた変数） |
| `0$:`、`jr z, 0$` | `関数名.区間_0`（普通のラベルの間だけで有効な、数のラベル） |
| `2(ix)` | `(ix+2)` |
| `or a, x` | `or x` |
| `.db` `.dw` `.ds` | `db` `dw` `ds` |

アセンブラは、hlang の `AsmFn`（名前、引数とレジスタ、戻りの型、命令の並び）になります。呼び方は `extern fn` と同じで、番地の代わりに名前のラベルを呼びます。壊すレジスタは命令から求めます（中のラベル以外へ飛ぶ・呼ぶ命令があれば、全部壊すとみなす）。参照インタプリタは、アセンブラの関数を実行できません。

- **本体がアセンブラだけの `__naked` 関数**（引数を書いただけの文 `hl;` は除く）は、引数を SDCC の呼び出し規約（`__sdcccall(1)`）のレジスタで受ける `AsmFn` にします。1 つ目の引数は、8 ビットなら A、16 ビットなら HL です。2 つ目は、1 つ目が A なら L か HL、1 つ目が HL なら E か DE です。戻り値は A（8 ビット）です。3 つ目からの引数（SDCC はスタックで渡す）と、16 ビットの戻り値（SDCC は DE で返す）は、まだ受けません。
- **関数の途中のアセンブラ**は、引数のない `AsmFn`（`関数名.asmN`。最後に `ret` を足す）に切り出して、その場所から呼びます。全部のレジスタを壊す呼び出しなので、生きている値は push / pop で守られます。
- アセンブラが `_name` で参照する C の変数は、メモリに置きます（定数に畳み込まない）。アセンブラから呼ばれる C の関数も、ROM に入れます。

## SDCC に合わせたこと（damaxian の C 版から）

- **static の名前はファイルごと。** 2 つ以上のファイルにある同じ名前の `static`（damaxian では `spriteOffset` や `count`）や、大域の名前とぶつかる `static` は、`名前.ファイルの番号` にします。アセンブラの `_name` も、そのファイルの名前として引きます。
- **割り込みと main の両方から呼ぶ関数は、割り込み用に複製する。** hlang は局所変数を固定の番地に置くので、同じ関数を割り込みからも main からも呼ぶと、変数が壊れます（8 章）。`&関数` で番地を取られる関数（割り込みの入口）からたどれる関数のうち、main からもたどれるものは、`名前.isr` という複製を作り、割り込みの側からの呼び出しを複製へ付け替えます。
- **本体が C の `__naked` 関数は、次の関数へ落ちる。** SDCC は `__naked` の関数に `ret` を出さないので、最後まで来ると、同じファイルのすぐ後ろの関数を続けて実行します。damaxian の `AppInitialize` は、そのまま `AppLoad` を実行しています。hlcc も、最後に次の関数を呼びます。
- **代入は右辺を先に計算する。** C では `a[f()] = g()` の f と g のどちらが先かは決まっていませんが、SDCC（と clang）は右辺が先です。damaxian の `TitleLoop` は `colorTable[乱数] = colorAnimationTable[乱数]` で、順が逆だと色と位置が入れ替わります。左辺に副作用があるときは、右辺を一時変数に受けてから左辺を計算します。

### damaxian の C 版で確かめたこと

damaxian の C 版（14 ファイル）は、そのまま hlcc でコンパイルできます。hlang 版（アセンブラ版と同じ動き）と、`examples/damaxian_hl/tools/handler-time.tcl` と同じキー入力で走らせ、自機、自機の弾、敵、敵の弾の RAM を毎フレーム比べました。乱数の種 4 通り、3000 フレームで一致します。ただし、比べる前に次のことをしています。

- スペースを押した瞬間の、タイトルの数え（`count`）を 1 にそろえる。起動処理の長さが違うと、この値が違い、タイトルで使う乱数の数がずれる。
- C 版のソースの、アセンブラ版と違う 2 か所を直す。Enemy.c の `if (ix->count0 == 0) ix->count0 -= 2;`（アセンブラ版は `!= 0`）と、Bullet.c の `ix->xi > 0xc4 || ix->yi > 0xc4`（アセンブラ版は `>=`）。
- 違って当然の欄は比べない。絵の表の ROM 番地と、動きに効かない phase（消えた自機の弾と、接近の状態の敵）。

C 版のソースのままで、割り込み処理 1 回の平均は 43,617T（種 4 通り、3000 フレーム、タイトルの数えをそろえて）です。hlang の 02-tuned 版（examples/damaxian_hl の本体）は 42,871T です。

## テスト

`test/c/*.c` を、参照インタプリタ、最適化なし、最適化ありの 3 通りで走らせ、出力を `test/c/*.out` と比べます（[test/t_c.ml](../test/t_c.ml)）。`*.out` は、同じ C を clang（`-funsigned-char -fpack-struct=1`）で走らせた出力です。テストに使う C は、clang の int（32 ビット）と結果が同じになるよう、16 ビットを超える計算を書きません。

## まだできないこと

- `goto`、ラベル、関数ポインタでの呼び出し、可変長引数、ビットフィールド、32 ビットの型、大きさを書かない配列で、要素の `{ }` を省いた初期化子、指示付きの初期化子（`.x = 1`）。
- `switch` の落ち抜け（break のない枝）と、枝の途中の `break`。
- 変数どうしの掛け算（hlang が、片方が定数の掛け算だけを書けるため）。
- アセンブラの関数で、3 つ以上の引数と 16 ビットの戻り値。アセンブラから、引数のある C の関数を呼ぶこと（呼び出し規約が違う）。
- 局所変数を、アセンブラから参照すること（SDCC はスタックに置くが、hlcc はレジスタか固定の番地に置く）。

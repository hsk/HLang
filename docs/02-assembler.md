# 2. アセンブラと逆アセンブラ

## 命令をデータで持つ

コンパイラは文字列ではなく、命令のデータを作ります（[src/asm.ml](../src/asm.ml)）。

```ocaml
type arg =
  | R of string                  (* レジスタ名か条件名: a hl nz ... *)
  | I of e                       (* 即値 *)
  | M of arg                     (* (…) メモリ参照 *)
  | X of string * e              (* ix+d。M の中に置く *)

type line = Ins of (string * arg list) | Label of string | Db of e list | ...
```

`ld a,(hl)` は `Ins ("ld", [R "a"; M (R "hl")])` です。同じデータから、機械語（`assemble`）と読めるテキスト（`show`）の両方を作ります。テキストは `z80asm` がそのまま読める書き方にしてあります。

## 番号がそのまま命令コードになる

オペランドを分類する関数が、命令コードに入る番号を返します。

```ocaml
let r8 = function                (* b c d e h l (hl) a *)
  | M (R "hl") -> Some 6
  | R r -> index r [ "b"; "c"; "d"; "e"; "h"; "l"; ""; "a" ]
```

`ld r,r'` は `0x40 + 8 * y + z` です。エミュレータの章で見た x y z の区切りを、逆向きに使っているだけです。

IX/IY もエミュレータと同じ考え方です。HL の命令として組み立ててから、前置バイトと変位 d を差し込みます（`enc`）。

## 逆アセンブラで自分を検査する

[src/dis.ml](../src/dis.ml) は、機械語を同じ命令データに戻します。アセンブラの逆関数です。すると次の検査ができます。

1. すべての命令コードを逆アセンブルする。
2. それを組み立て直す。
3. 元のバイト列と一致することを確かめる。

公式の全 697 命令がこの往復で一致します。さらに同じ命令をテキストにして外部の `z80asm` にも組み立てさせ、バイト列が一致することも確かめています（[test/t_asm.ml](../test/t_asm.ml)）。

## コストは表を持たずに測る

最適化には、命令の大きさと時間が要ります。[src/cost.ml](../src/cost.ml) は表を持ちません。

- 大きさ：実際に組み立てて、長さを見る。
- 時間：組み立てた命令をエミュレータで 1 回走らせて、進んだ T ステートを見る。条件付きの命令は、成り立つ場合と成り立たない場合の両方を走らせる。

アセンブラ・エミュレータと食い違うことが、仕組みの上で起きません。

## 命令が書き換えるレジスタ

コード生成は「この命令はどのレジスタを書き換えるか」を知る必要があります（`writes`）。これは表ですが、間違うと静かに壊れたコードが出るので、エミュレータで検査します。全命令をレジスタの値を変えながら走らせ、変化したレジスタがすべて表に入っていることを確かめています。

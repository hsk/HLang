# 5. コード生成と置き場所の探索

この章が hlang の中心です。HL を活かしたコードと、関数ごとの呼び出し規約がここで決まります。

## 結果から

```text
fn sum(p: u16, n: u8) -> u8 {
  var acc: u8 = 0
  while n != 0 { acc += mem[p]  p += 1  n -= 1 }
  return acc
}
```

最適化なし（`-O0`）では、変数をすべてメモリに置きます。ループ 1 周に十数命令かかります。最適化ありでは次のコードになります。

```asm
; fn sum(p.1: HL, n.2: B) -> A
sum:
    xor a
    inc b
    djnz sum.loop.3.body
    ret
; loop loop.3(acc.5: A, n.6: B, p.7: HL)
sum.loop.3.body:
    add a,(hl)
    inc hl
    djnz sum.loop.3.body
    ret
```

コメントの `loop.3(acc: A, n: B, p: HL)` は、継続の引数がどのレジスタに入って来るかの約束です。関数の先頭の `sum(p: HL, n: B) -> A` は、この関数の呼び出し規約です。どちらもコンパイラが選びました。固定の規約はありません。

同じ仕組みで、`copy(dst, src, n)` は `copy(dst: DE, src: HL, n: BC)` になります。

## 置き場所

変数にはそれぞれ「置き場所」があります。

- レジスタ：`a b c d e h l`（8bit）、`hl de bc`（16bit）
- メモリ：固定番地。再帰がないので、スタックフレームは要りません。

関数の引数の置き場所が、そのまま呼び出し規約です。呼ぶ側は、相手の引数の置き場所へ値を入れてから `call` します。

### コード生成は自分で安全を確かめる

コード生成は、レジスタを書き換える命令を出すたびに、「生きている変数の置き場所を壊さないか」を調べます。壊すなら例外 `Stuck` を投げます。

```ocaml
let emit c op args =
  let w = writes (op, args) in         (* この命令が書き換えるレジスタ *)
  guard c w;                           (* 生きている値を壊すなら Stuck *)
  ...
```

この検査があるので、割り当てる側は「2 つの変数が同時に生きているか」を前もって計算しなくて済みます。無理な割り当てを渡せば、単に `Stuck` になって不採用になるだけです。全部メモリに置く割り当ては、必ず成功します。

### 割り当ては測って決める

1. 全部メモリに置く。これが出発点です。
2. 受け渡しのある変数どうし（継続の引数と渡す値、演算の結果と元の値）を、同じ置き場所にまとめてみる。コストが悪くならなければ採用。受け渡しの命令が消えます。
3. まとまりごとに、各レジスタへ置いてみる。いちばん安くなる置き場所を採用。重い変数（ループの中でよく使う変数）から順に試します。
4. 3 を、良くなる間は繰り返す（5 周まで）。周りの置き場所が決まって初めて置ける場所があります。たとえば、足し算の結果を A に置くと決まった後でなら、ポインタを HL に置いて `add a,(hl)` で読めます。
5. 3 では、「x を h へ動かし、h にいた同じ型のまとまりを x の元の場所へ押し出す」入れ替えも試します。1 つずつ動かすだけでは、2 つのまとまりが互いの場所を取り合って動けないことがあります。たとえば、`at` が DE、相手の値が HL にあるとき、入れ替えれば足し算の結果が HL に残り、`ld d,h / ld e,l` と作業用の BC が要らなくなります。
6. 3〜5 を、並べ方を変えてもう一度初めから行い（8bit のまとまりを先に）、安いほうを採ります。3 つ以上を同時に動かさないと良くならない所では、1 つずつ動かす探索は止まります。damaxian の BulletMove では、B, C にいる 16bit の値を DE へ、D, E にいる 8bit の値を B, C へ、まとめて動かす必要がありました。最適化ありのコンパイルは、そのぶん倍ほどかかります（damaxian で 1.4 秒から 2.6 秒）。

コストは、出てきたコードの実行時間と大きさです（[src/cost.ml](../src/cost.ml) の `price`）。命令の時間はエミュレータで測った値です。行ごとに「何回実行されそうか」の重みを付けてあり、ループの中は 1 段につき 8 倍、`match` の枝分かれの中はそこを通る割合だけ数えます（6 章）。

関数は、呼ばれる側から先に決めます。呼ぶ側は、相手の引数の置き場所と、相手が壊すレジスタを見て、自分の割り当てを決められます。

試す回数には関数ごとに上限があります。大きな関数ほど 1 回の手間がかかるので、回数を減らします。重い変数から試すので、上限に達しても大事な変数は済んでいます。

この探索は貪欲法で、最適であることは保証しません。それでも、Z80 の不規則なレジスタ（A でしか演算できない、HL でしかメモリを指せない命令が多い）に対して、規則を書き並べる代わりに「出して測る」で済むのが利点です。

## HL を活かすところ

コード生成は、HL に置かれた値を次のように使います。

- `mem[p]` で `p` が HL なら `ld a,(hl)`。直後に演算へ使うなら `add a,(hl)` のように 1 命令にまとめます。
- `p + 1` で、結果も `p` と同じ HL なら `inc hl`。
- 16bit の大小比較は、A だけを使って下位から引きます。HL の値は壊しません。
- 16bit の一致比較で HL を引き算に使ったら、`add hl,de` で足し戻します（`add hl` は Z フラグを変えません）。

IX/IY は今のところ使いません。

## フラグを覚えておく

コード生成は「Z フラグが、どの変数が 0 かどうかを表しているか」を覚えています（`zf`）。

- `dec b` の直後に「`b` が 0 か」で分岐するなら、比較の命令を出しません。
- フラグを変える命令を出したら、覚えを消します。`ld` や 16bit の `inc` はフラグを変えないので、覚えは残ります。

同じように、A と HL に入っていると分かっている値も覚えていて、同じ値の読み直しを省きます。

## ループの判定を末尾に回す

`while` は、中間表現では「先頭で条件を調べる継続」です。そのまま出すと、1 周ごとに「先頭へ飛ぶ」「条件を調べて抜けるか決める」の 2 回分岐します。

そこで、ループの先頭へ飛ぶ代わりに、飛ぶ場所で条件を調べて、本体へ直接飛びます。直前の `dec` のフラグが残っていれば、比較も要りません。`dec b` と `jp nz` が並んだら、`djnz` 1 つにします。先頭の判定は、誰も飛んでこなくなれば消えます。

## インライン展開（Inline）

`inline fn` と書いた関数と、とても小さい関数（中間表現で 8 項まで）は、呼ぶ所に本体を展開します（[src/inline.ml](../src/inline.ml)）。ほかの最適化より先に、関数をまたいで行います。

- `let x = f(a, b); 続き` は、`LetK ([ret(x) = 続き], let p = a; let q = b; <f の本体>)` になります。f の本体の `return v` は `ret(v)` へのジャンプです。
- 展開する本体の変数と継続は、名前を付け替えます（関数の中で、名前は 1 つずつ）。
- 展開した関数の中の呼び出しも、3 段まで展開します。番地を取られている関数（`&f`）は、展開しても残ります。
- 自動で展開する大きさ（8 項）は、damaxian で 0、4、8、12 項を試して決めました。

## 壊すレジスタの約束（clobbers）

関数ごとの壊すレジスタは、呼ばれる側から先に割り当てて調べてあり、呼ぶ側はそれを見て、呼び出しをまたぐ値の置き場所を決めます（[src/alloc.ml](../src/alloc.ml) の `clobs`）。`fn ... clobbers(...)` と書いた関数は、その約束を守るように出します（`keep`）。

- 引数の置き場所の候補を、書いたレジスタに絞る。
- 約束にないのに壊すレジスタの組を、入口で `push` する。`ret` は `pop ...; ret`、`ret cc` は `jp cc,f.out`（`f.out: pop ...; ret`）、末尾呼び出しの `jp g` は `call g; pop ...; ret` にする。自分の入口へ戻るループは、`push` の後（`f.in`）へ飛ぶ。
- これは割り当ての探索の中でかけるので、`push` / `pop` の手間も値段に入る。探索は、約束にないレジスタをなるべく避ける。
- 呼ぶ側には、書いたレジスタ（と戻り値のレジスタ）だけを「壊す」と伝える。

調べた結果は、アセンブリの関数の頭に `clobbers(...)` の形で書き足します（`show_clob`）。

約束で使えるレジスタが減ると、関数そのものは遅くなることがあります。初め、damaxian の SystemSetSprite に `clobbers(a, bc, de, hl)` を付けると、本体が `(ix+n)` を使えずに崩れました。ポインタが 2 本あり、歩けるのが HL だけだったためです。DE, BC も歩けるようにした（下の「ポインタを歩く」）後は、注釈を付けなくても、探索が IX を使わない形を選ぶようになりました。

## ポインタを歩く

`mem[p]`、`mem[p + 1]`、`mem[p + 2]` のように、同じポインタから続けて読み書きするとき、p を置いたレジスタそのものを `inc` で進め、どれだけ進めたか（`ofs`）を覚えておきます（[src/gen.ml](../src/gen.ml) の `walk`）。p を本来の値として使う命令の前や、合流の前で、`dec` で戻します（`settle`）。戻る前に p が要らなくなれば、戻す命令も出しません。

- HL は `(hl)` で、どのレジスタとも読み書きできます。
- DE, BC は `ld a,(de)`、`ld (de),a` のように、A とだけ読み書きできます。それ以外の形は、HL で番地を作る元のやり方に戻ります。
- IX, IY は進めずに `(ix+n)` で指します。

ポインタが 2 本あるとき（写し元と写し先など）、両方を歩けるので、HL で番地を作り直さずに済みます。

```
    ld a,(de)       ; mem[p]
    add a,h
    ld (bc),a       ; mem[q] = ...
    inc de
    ld a,(de)       ; mem[p + 1]
    ...
    inc bc
    ld (bc),a       ; mem[q + 1] = ...
```

## 16bit の計算を 8bit に狭める（Narrow）

言語は u8 と u16 を混ぜると u16 で計算します。`hl += ((ix.angle + 0x20) & 0xc0) >> 3` は、そのままだと 16bit で足し、16bit で and し、`srl h / rr l` を 3 回します。0xc0 で切り取った後は上位が 0 なので、下位だけを 8bit で計算すれば済みます（[src/narrow.ml](../src/narrow.ml)）。

- `x & m`（m は 0xff 以下）: 下位バイトだけを 8bit で計算して、最後に広げます。足し算、引き算、論理演算、左シフトの下位バイトは、元の値の下位バイトだけで決まります。
- `(8bit を広げた値) >> n`: 8bit のままシフトします。
- 16bit の読み `mem16[a]` の使い方が、全部「下位（`as u8`）」か「上位（`>> 8`）」なら、`a` と `a + 1` を 1 バイトずつ読みます（`ld a,(ix+3)`）。
- 使われなくなった計算と読みは、なくなるまで繰り返し消します。ポートの読みは残します。

## 構造体の配列を歩くポインタ（Iv）

`for b in 0..9 { ... enemies[b].x ... enemies[b].y ... }` の `enemies[b]` の番地は、そのままだと `b * 17` の掛け算（シフトと足し算）で、使うたびに作ります。そこで、ループに 16bit の引数を 1 つ足し、入口で `&enemies[0]`、1 周ごとに 17 を足して渡します（[src/iv.ml](../src/iv.ml)。帰納変数の強度低減）。本体の `&enemies[b * 17]` はその変数になり、`continue` で次の周へ飛ぶ所にも渡します。

割り当ては、この変数を IX や IY に置くことが多く、欄は `ld a,(ix+10)` で直接読めます。進めるのは `ld de,17` と `add ix,de` です。掛け算のない `&s[i]` は、番地を作る手間が小さいので対象にしません。前提は Ptr と同じで、添字が表の外を指さないことです。

置き換えた後、添字が回数を数えるだけになったループ（本体が添字を使わない）は、n から 0 へ数え下ろします。判定が「0 でないか」になり、減らす命令を飛ぶ直前に置くので、B に置けば `djnz` 1 つ（13T）です。上へ数えると `inc b / ld a,b / cp n / jp c`（25T）かかり、A も使います。

## ブロック転送と I/O のループ（Blk）

コピーや塗りつぶしを 1 バイトずつのループで書いても、`ldir` などの 1 命令にします（[src/blk.ml](../src/blk.ml)）。1 バイトあたり、ループは 60T 以上、`ldir` は 21T です。割り当ての前、中間表現の上で、形が合うループだけを置き換えます。

| 書き方 | 出る命令 |
| --- | --- |
| `for i in 0..n { dst[i] = src[i] }` | `ldir` |
| `var i = n  while i != 0 { i -= 1  dst[i] = src[i] }` | `lddr`（終わりの番地から後ろへ） |
| `dst[i] = v`（`v` はループによらない値、どちらの向きでも） | `.fill`（`ld (hl),a` のあと `ldir` する小さなルーチン） |
| `port[P] = mem[p + i]`（上へ、下へ） | `otir`、`otdr` |
| `mem[p + i] = port[P]`（上へ、下へ） | `inir`、`indr` |

- **向きはループのとおり**にします。`ldir` は前から、`lddr` は後ろから 1 バイトずつ写すので、番地が重なる写しも、元のループと同じ結果になります。重なる写しで向きを取り違えると壊れるので、上の `for` は `ldir`、下へ数える `while` は `lddr` と、決めています。塗りつぶしは順序が結果に響かないので、向きによらず前から埋めます。
- 回数 `n` が変数なら、0 のときは何もしません（`ldir` は 0 を 65536 と数えるため）。回数が定数で小さいとき（コピー 1 以下、塗りつぶし 3 以下、I/O 2 以下）は、ループのままにします。
- ループを抜けた後の `i` は、上へなら `n`、下へなら 0 のままです。
- 本体に、ほかの文や `break` が混ざる、添字が 1 ずつではない、などの形は、そのままループにします。

置き換えが合っているかは、`test/t_lang.ml` の「ブロック転送のループ」「ポートへ書く・読むループ」が、重なる写し、0 個、定数と変数の回数、両方の向きをインタプリタと機械語で比べて確かめます。

## 仕上げ

出したコードに、小さな置き換えをかけます（`tidy`）。

- すぐ次の行へのジャンプを消す。
- 飛び先がすぐ `ret` なら、条件付きの `ret` にする。
- `call` の直後が `ret` なら、`jp` にする。
- 無条件に飛んだ後の、誰も飛んでこないコードを消す。
- 読まれる前に上書きされる 8bit レジスタへの `ld` を消す。ラベルや、飛ぶ・呼ぶ・戻る命令に当たったら、生きているとみなして止める。
- 割り当てが決まった後のコードにだけ: 結果が読まれない 16bit の `inc` / `dec`（16bit の読み書きの後の `dec hl` など）と、`ld r,a` のすぐ後の `ld a,r` を消す。探索の値段に入れると、値段の小さな違いで探索が別の割り当てに落ち、かえって遅くなったので、最後にだけかける。
- 前へ飛ぶ条件付きの `jp` は、近ければ `jr` にする（[src/cost.ml](../src/cost.ml) の `short`）。

`jr` は成り立たないとき 7 T、成り立つとき 12 T です。`jp` はどちらも 10 T です。前へ飛ぶ分岐は成り立たないことが多いので `jr` が得ですが、後ろへ飛ぶ分岐（ループの戻り）はたいてい成り立つので `jp` のままにします。無条件のジャンプも `jp` の方が 2 T 速いので、そのままです。

値段を付けるときも、この違いを数えます。行の重みが次の行で減っていれば、減った分が「飛んだ回数」です。たとえば 4 つの枝を順に比べるとき、最初の `jr z` は重み 4/4、次の行は 3/4 なので、4 回に 1 回だけ 12 T と数えます。

置き換えた後のコードでコストを測るので、探索は `djnz` が使える B レジスタを自然に選びます。

# 6. インタプリタを書くための部品

hlang の出力は機械語だけです。ここで言うインタプリタは、hlang で**書く**ものです。音楽ドライバのバイトコードマシンや、ゲーム進行データの実行器がその例です。そのための部品が 4 つあります。

## 例

[examples/script.hl](../examples/script.hl) は、文字を出すだけの小さなバイトコードマシンです。

```text
enum Op { PUT, REP, NL, END }

data script: u8 = [
  PUT, 'H', PUT, 'L', REP, 3, '!', NL,
  REP, 5, '*', NL,
  END,
]

fn run(p: u16) {
  loop {
    match next(p) as Op {
      PUT => { chput(next(p)) }
      REP => {
        var n = next(p)
        var c = next(p)
        while n != 0 { chput(c)  n -= 1 }
      }
      NL => { chput(13) chput(10) }
      END => { return }
    }
  }
}
```

出力は次のとおりです（抜粋。右側のコメントは説明のために足したものです）。

```asm
; fn run(p.1: HL)
run:
; cont loop.2(p.4: HL)
run.loop.2:
    ld a,(hl)            ; 命令を読む
    inc hl
    or a
    jr z,run.case.12     ; PUT
    dec a
    jr z,run.case.22     ; REP
    dec a
    jr z,run.case.23     ; NL
    ret                  ; END（比べずに入る）
; cont case.22()
run.case.22:
    ld b,(hl)            ; n
    inc hl
    ld a,(hl)            ; c
    inc hl
    inc b
    dec b
    jp z,run.loop.2
; loop loop.17(n.19: B)
run.loop.17.body:
    call 0xa2
    djnz run.loop.17.body
    jp run.loop.2
```

読み取り位置 `p` は、関数を通して HL に置かれます。

## 部品

### 列挙型

```text
enum Op { PUT, REP, NL, END }      // 値は 0 から順。PUT = 0x10 のように指定もできる
```

1 バイトの値です。数とは別の型なので、混ぜるときは `as u8` や `as Op` と書きます。

### match と網羅性チェック

`match` は値で枝分かれします。列挙型の値を調べるとき、`_ =>` を書かなければ、すべての名前を書く必要があります。抜けがあるとコンパイルエラーになります。

```text
test.hl:12: match に抜けがある: NL
```

命令を 1 つ足したら、扱い忘れている `match` をコンパイラが全部教えてくれます。

網羅されていると分かるので、最後の枝は比べずに入ります。上の例では `END` の比較がありません。その代わり、`as Op` で変換した値が本当にその列挙型の値であることは、書く人の責任です。範囲外の値が来たときの動きは決まっていません。

`u8` の値を直接 `match` するときは、`_ =>` が必要です。

### match の出し方は測って選ぶ

値で枝分かれするコードの出し方は 3 通りあります。

| 出し方 | コード | 向いている場面 |
| --- | --- | --- |
| 順に比べる | `or a` / `jr z` / `dec a` / `jr z` … | 枝が少ない。書いた順に調べるので、先に書いた枝ほど速い |
| 2 分探索 | `cp 真ん中` / `jr c` で半分に割り、残りが数個になったら順に比べる | 枝が中くらい。値がとびとびで表にできない |
| 表で飛ぶ | 値で飛び先の表を引いて `jp (hl)` | 枝が多い。時間が枝の数によらない |

どれが速いかは枝の数だけでは決まりません。表は HL を使うので、読み取り位置を HL から DE へ移す必要があり、その分だけ他の所が遅くなります。順に比べる形と 2 分探索は A しか使いません。そこでコンパイラは決め打ちの境目を持たず、**全部出してみて、いちばん安いものを採ります**。置き場所の探索（5 章）が割り当てを 1 つ試すたびに、その割り当ての下で 3 通りを出して比べるので、「HL に置いて順に比べる」と「DE に置いて表で飛ぶ」も同じ土俵で比べられます。

値段は 5 章と同じで、エミュレータで測った命令の時間と、大きさです。飛び先が近ければ分岐は `jr` になるので（5 章）、枝の本体を先に出しておき、そこまでの距離を見て値段を付けます。枝分かれの中の命令には「そこを通る割合」を掛けます。どの枝も同じ頻度で来るとみなすので、8 個の枝を順に比べるなら、最初の比較は毎回、最後の比較は 8 回に 1 回と数えます。表は 256 バイト境界に置くので、1 つ 256 バイトと数えます。ループの中では時間が重く、外では大きさが効くので、ループの外の `match` はなかなか表になりません。

順に比べるときの小技が 2 つあります。

- 値が続き番号なら、`cp n` の代わりに `dec a` で A を減らしながら調べます（7 T・2 バイトが 4 T・1 バイトになる）。値を後で使うために A を壊せないときは、`cp n` のままです。
- 残りの値が全部同じ行き先だと分かったら、比べずに飛びます。網羅されている `match` の最後の枝がこれです。

### 実測

[test/sw.ml](../test/sw.ml) は、枝の数を変えながら 3 通りを強制して出し、エミュレータで走らせます。n 個の命令を同じ回数ずつ実行するバイトコードマシンで、命令 1 つあたりの T ステート（読み出しと本体を含む）と、プログラム全体のバイト数です。「自動」がコンパイラの選んだものです。

```sh
dune exec test/sw.exe          # 値が 0 から続き番号
dune exec test/sw.exe -- 9     # 値が 9 おき
```

値が続き番号のとき：

| 枝 | 順に比べる | 2 分探索 | 表 | 自動 |
| --- | --- | --- | --- | --- |
| 2 | 41.4 T / 59 B | 44.4 T / 61 B | 68.2 T / 386 B | 順 |
| 3 | 42.5 T / 84 B | 45.5 T / 87 B | 63.4 T / 387 B | 順 |
| 4 | 49.0 T / 119 B | 54.1 T / 143 B | 61.7 T / 388 B | 順 |
| 5 | 55.7 T / 161 B | 56.9 T / 189 B | 60.8 T / 389 B | 順 |
| 6 | 62.6 T / 210 B | 60.4 T / 247 B | 60.2 T / 390 B | 60.0 T / 233 B（順と 2 分の組み合わせ） |
| 7 | 69.4 T / 305 B | 63.6 T / 311 B | 59.9 T / 391 B | 表 |
| 8 | 76.4 T / 336 B | 67.9 T / 386 B | 59.6 T / 392 B | 表 |
| 12 | 99.6 T / 206 B | 88.0 T / 221 B | 59.0 T / 652 B | 表 |
| 16 | 121.4 T / 377 B | 93.5 T / 377 B | 58.8 T / 656 B | 表 |
| 32 | 252.2 T / 761 B | 111.6 T / 761 B | 58.4 T / 928 B | 表 |

- 5 個までは順に比べるのが速く、7 個から表になります。
- 続き番号では、2 分探索の出番はほぼありません。出番は、値がとびとびで表にできないときです。値が 9 おきだと 5〜6 個で 2 分探索が選ばれ、値が 128 以上になる 16 個では 97.4 T（順に比べると 142.5 T）の 2 分探索になります。
- 9 個までの「順に比べる」「2 分探索」が大きいのは、下で説明する複製のためです。枝が増えると複製が割に合わなくなり、10 個からは複製しません。

### 分岐を枝の終わりに複製する

バイトコードを読んで分岐するループは、素直に出すと、枝の本体が終わるたびにループの先頭へ `jp` で戻ります。命令 1 つにつき 10 T です。

そこで、飛び先が「短い一本道で、値での分岐で終わる」なら、飛ぶ代わりにそのコードを飛ぶ場所へ複製します。`while` の判定を末尾に回すのと同じ考えです（5 章）。表で飛ぶ形なら、各枝の終わりがこうなります。

```asm
; cont case.22()                 ; ADD
run.case.22:
    ld a,(de)
    dec de
    ld h,d
    ld l,e
    add a,(hl)
    ld (de),a
    ld a,(bc)                    ; ここから次の命令の読み出しと分岐。先頭へは戻らない
    inc bc
    ld l,a
    ld h,(run.table1)>>8
    ld a,(hl)
    set 7,l
    ld h,(hl)
    ld l,a
    jp (hl)
```

複製するかどうかも値段で決めます。浮くのは `jp` 1 つの時間、増えるのは複製の大きさです。枝の本体は「枝の数分の 1」しか通らないので、その重みで `jp` の時間を数えます。表で飛ぶ形（14 バイト）は枝が 30 個近くまで複製され、順に比べる形のような大きなコードは、枝が増えると複製されなくなります。飛び先の表は、複製どうしで 1 つを共有します。

### 手書きアセンブリとの比較

`bench/vm.sh` は、8 命令のバイトコードマシン（1601 命令を実行）を、hlang と手書きアセンブリで比べます。

| 版 | 時間 | 命令 1 つあたり |
| --- | --- | --- |
| hlang、手書きと同じ書き方（[bench/vm_top.hl](../bench/vm_top.hl)） | 142,413 T | 89 T |
| 手書き、スタックはメモリ（[bench/vm.asm](../bench/vm.asm)） | 146,348 T | 91 T |
| 手書き、CPU のスタック（[bench/vm_sp.asm](../bench/vm_sp.asm)） | 153,978 T | 96 T |
| hlang、`mem[sp - 1]` で書く（[bench/vm_ptr.hl](../bench/vm_ptr.hl)） | 157,986 T | 99 T |
| hlang、`stack[sp]` で書く（[bench/vm.hl](../bench/vm.hl)） | 157,986 T | 99 T |

- 手書きと同じ持ち方（ポインタがスタックの一番上を指す）で書けば、hlang の方が速いです。枝の本体はほぼ同じコードで、差は上の複製（命令ごとに 10 T）から来ています。手書き版も同じことをすれば追い抜けますが、8 か所に同じコードを書くことになります。
- 表で飛ぶコードそのものは、手書きの方が 4 T 速いです（表を 2 ページに分けて `inc h` で上位を読む。その代わり表が 256 バイト増える）。
- `stack[sp]` と書いても `mem[sp - 1]` と書いても、同じコードになります（下の「添字をポインタに直す」）。手書きとの差は 1.08 倍です。
- 残りの差は、ポインタの向きです。普通に書くと `sp` は「次に積む場所」を指すので、一番上の要素は `sp - 1` にあり、読むたびに HL へ写して 1 引きます。手書き版と `vm_top.hl` は「一番上の要素」を指すので、そのまま読めます。コンパイラがポインタの向きを選び直す最適化は、まだありません。

### 添字をポインタに直す

```text
var stack: [u8; 16]
var sp: u8 = 0
...
LIT => { stack[sp] = next(p)  sp += 1 }
ADD => { sp -= 1  stack[sp - 1] = stack[sp - 1] + stack[sp] }
```

素直に出すと、`stack[sp]` のたびに「`stack` の番地 + `sp`」を計算します（22 T）。そこで、`sp` が「`stack` を引く」「定数を足し引きする」ことにしか使われていないなら、`sp` の代わりに番地 `stack + sp` を変数にします（[src/ptr.ml](../src/ptr.ml)）。

```asm
; cont case.17()                 ; LIT
    ld a,(bc)
    inc bc
    ld (de),a                    ; stack[sp] = …   DE が番地そのもの
    inc de                       ; sp += 1
; cont case.27()                 ; ADD
    dec de                       ; sp -= 1
    ld h,d
    ld l,e
    dec hl
    ld a,(hl)                    ; stack[sp - 1]
    inc hl
    add a,(hl)                   ; + stack[sp]
    dec hl
    ld (hl),a                    ; stack[sp - 1] = …
```

やっていることは次のとおりです。

- **仲間を見つける**：中間表現では変数は一度しか束縛されないので、`sp` は「継続の引数」「そこへ渡す値」「定数を足し引きした結果」でつながった変数の集まりになっています。その全員が上の使われ方だけをしていれば、全員を 8bit の添字から 16bit の番地に取り替えます。名前はそのまま、型だけが変わります。
- **比べたり、他へ渡したりしていたら、やらない**：`if r == 4 { r = 0 }` のように添字そのものの値を使っていれば、添字のままです。
- **途中の値は変数にしない**：`sp - 1` のような値は、持ち歩いている番地からのずれとして、読み書きの直前で計算し直します。コード生成が読み書きと 1 つにまとめます。
- **HL の位置を覚えておく**：番地が DE や BC にあるとき、`mem[p - 1]` は HL へ写して 1 引いてから読みます。続けて `mem[p]` を読むなら、写し直さずに `inc hl` で済ませます（[src/gen.ml](../src/gen.ml) の `near`）。

前提が 1 つあります。**添字が表の外を指さないこと**です。8bit の添字は 255 の次が 0 に戻りますが、番地は戻りません。256 バイトちょうどの表は、添字が一周することを当てにした書き方（リングバッファ）がありうるので、対象にしません。

この計測は、最後の命令（終了）だけ 1 回しか実行しません。「どの枝も同じ頻度」という見積もりとは少しずれるので、0.5 T ほどの差では見積もりと実測の順位が入れ替わることがあります。

### next で読み進める

```text
var op = next(p)       // p の指す 1 バイトを読んで、p を 1 進める
var w = next16(p)      // 2 バイト読んで、p を 2 進める
```

`p` は `u16` の変数です。`p` が HL に置かれていれば、`ld a,(hl)` / `inc hl` になります。

`next` は、その文が始まる前に実行されます。1 つの文に 2 回書けば、左から順です。`while` の条件と、`&&` `||` の右側には書けません（何回実行されるかが式から決まらないため）。

### 表と配列

```text
data script: u8 = [PUT, 'H', END]     // ROM に置く表。u8 の表には列挙の名前も書ける
data notes: u16 = [0x1ac, 0x194]      // 16bit の表
data title: u8 = "HLANG"              // 文字列でも書ける
var buf: [u8; 16]                     // RAM に置く配列
```

名前は先頭の番地（`u16`）になります。`notes[i]` と書けば、要素の大きさを掛けて読み書きします。

## 作り

`match` の出し方（[src/gen.ml](../src/gen.ml) の `tree` と `table`）を除けば、どれも型検査（[src/check.ml](../src/check.ml)）と CPS 変換（[src/cps.ml](../src/cps.ml)）で、すでにある仕組みに直しています。

`tree` は 1 つの関数で、順に比べる形と 2 分探索の両方を出します。「枝が `leaf` 個以下なら順に比べ、多ければ真ん中で割る」という作りで、`leaf` を大きくすれば全部を順に比べる形になります。候補は `leaf` を 1〜4 と無限大に変えたものと、表です。`trial` が候補を 1 つ出しては値段を測って取り消し、最後にいちばん安いものを出し直します。

| 部品 | 何に直すか |
| --- | --- |
| 列挙の名前 | 型の付いた定数 |
| `match` | 値ごとの飛び先を持つ `Switch`。枝の本体は引数なしの継続。出し方はコード生成が選ぶ |
| `next(p)` | 「読む文」と「進める文」。型検査が文の前に出す |
| `表[i]` | `mem[番地 + i × 大きさ]` |
